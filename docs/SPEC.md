# 任务：开发一款在手机上玩的数独游戏（iPhone 与 Android 同等优先；经典 + 4 种热门变体；完全离线；残局永久保存），完整、精致、零错误

你是资深移动端游戏开发者兼数独算法专家。请真正实现、运行、测试，不要给方案、伪代码或半成品。界面文字全部用简体中文。

## 0. 硬性原则
1. 所有题目由程序在手机本地实时随机生成。严禁内置题库，严禁用固定终盘做换数/换行变换冒充随机。
2. 每道题必须唯一解，且能用第 4 节规定的逻辑技巧解出；严禁需要猜测或试错的题。
3. 难度标签必须由人类技巧求解器真实评出，不许按提示数个数估算。做不到的档位就不显示，不许冒充。
4. 所有可见按钮都必须可用：不许有占位按钮、假数据、"敬请期待"。
5. 每完成一个里程碑，运行全部测试并汇报真实结果；测试未通过不许宣称完成。做不到的地方直接说明原因和替代方案。
6. iPhone 与 Android 同等优先：两端的功能、外观、流畅度、稳定性必须达到同样水准。
7. 我的存档和记录神圣不可丢：任何更新、异常、断电都不能导致存档丢失或损坏。

## 3. 模式与规则（以此为准，不得自行改约定）
"标准规则"：每行、每列、每宫各含 1–9 各一次。
1. 经典数独：9×9，3×3 宫，标准规则。
2. 对角线数独：标准规则 + 两条主对角线各含 1–9 不重复。
3. 锯齿数独：
   - 9×9，用 9 个形状不规则、各含 9 格、四连通的区域代替 3×3 宫；
   - 每行、每列、每个区域各含 1–9；
   - 区域布局每局随机生成，且必须存在合法终盘。
4. 杀手数独：
   - 标准规则；
   - 盘面被虚线"笼"完全覆盖，每格恰好属于一个笼；
   - 笼内数字之和等于笼左上角标注的数；
   - 同一笼内数字不得重复。
5. 武士数独：
   - 5 个 9×9 盘呈 X 形重叠：中间盘的 4 个角宫分别与 4 个角盘的内角宫共享，共 369 格；
   - 每个 9×9 盘各自满足标准规则；
   - 行、列只在各自的 9×9 盘内有效，21 格长的整行不是约束单元。

规则页以本节为准，可以润色，不能改变含义。

## 4. 难度（五档，按人类技巧阶梯评级）
- 实现"人类技巧求解器"，评级规则：
  - 每一步总是先用最简单的可用技巧；
  - 难度档 = 全程用到的最难技巧所在档位；
  - 同档内按技巧权重累加分数排序。
- 五档技巧阶梯：
  - 1 入门：最后一格、显性唯一（唯余）、隐性唯一（摒除）
  - 2 简单：+ 区块摒除（Pointing / Claiming）
  - 3 中等：+ 显性/隐性数对、三数组
  - 4 困难：+ 四数组、X-Wing、剑鱼、XY-Wing、XYZ-Wing、摩天楼、双线风筝、简单染色、空矩形
  - 5 专家：+ 水母、W-Wing、X-Chain、XY-Chain、交替推理链（AIC）、唯一矩形 1–4 型、BUG+1
- 用全部技巧仍解不出的题一律丢弃。
- 专家档是全游戏最高难度，必须真的需要第 5 档技巧才能解，不许拿困难题凑数。

各模式的处理：
- 对角线、锯齿：
  - 对角线和锯齿区域视为普通单元，参与所有基于单元的技巧；
  - 鱼类技巧只用于行和列；
  - 锯齿数独的区块摒除，按"行/列与不规则区域的交集"计算。
- 武士：
  - 每个子盘的行、列、宫都是单元；
  - 共享宫把相邻子盘联系起来，所有技巧都要跨子盘生效。
- 杀手专属推理（分档）：
  - 基础（1–2 档）：笼的唯一组合；组合与已填数的直接排除。
  - 进阶（3–4 档）：45 法则（宫/行/列的内格、外格求和）；笼组合与候选交叉排除；笼内锁定数字对单元的影响。
  - 专家（5 档）：多笼联立的 45 法则；组合分析与链类技巧的结合。
- 杀手给定数：
  - 入门到中等档可以有少量给定数；
  - 困难、专家档默认零给定数（纯杀手），确实需要时才加，且尽量少。
- 档位显示与校准：
  - 某模式达不到的档位，界面上不显示；
  - 用抽样测试校准，各档的解题步数和平均用时应随档位单调上升。

同一个技巧求解器同时驱动"提示"功能，保证提示讲的就是真实解法。

## 5. 生成流程
1. PRNG：可设种子的 xoshiro128** 或同等质量算法，种子来自 crypto.getRandomValues。
2. 终盘：用"随机候选顺序 + MRV"的回溯生成。
   - 对角线的终盘本身就要满足对角线约束。
   - 锯齿先随机生成区域布局（例如从标准宫出发，随机交换边界格并保持连通）；限时内找不到终盘就换布局。
   - 武士对 369 格整体回溯。
3. 杀手笼：
   - 从终盘随机生长；笼必须连通，笼内数字不得重复。
   - 以 2–4 格为主，偶尔 5 格；单格笼尽量少（单格笼等于直接给数）。
   - 通过笼的大小、形状和给定数调节难度。
   - 每次改笼都要重新检查唯一性。
   - 纯杀手不唯一时，优先重新分笼，其次才补最少的给定数。
4. 挖空：
   - 按随机顺序挖；1–3 档可选中心对称成对挖。
   - 每挖一次用唯一性求解器检查，找到第 2 个解立即停止。
   - 挖到极小或达到目标为止。
5. 评级：不符合目标档位就重试。先重新挖空或重新分笼，再换终盘。
6. 性能（两种平台都要满足，以中低端安卓为基准）：
   - 生成放在 Web Worker 中；Worker 不可用时退化为主线程分片生成，每片不超过 16ms 就让出。界面永不卡顿。
   - 目标耗时：
     - 9×9 模式：1–3 档小于 1 秒，4 档小于 5 秒；
     - 武士：1–3 档小于 3 秒。
   - 高难档题池：
     - 允许生成得更久；
     - App 在前台空闲时预生成题池：每模式每档 2 道，存 IndexedDB，取出即作废；
     - 不依赖后台运行；
     - 显示生成进度，可以取消。
   - 超时就如实提示，绝不拿低档题冒充高档。
7. 唯一性求解器：
   - 用位掩码实现；杀手的求和约束用"带传播的回溯 + 笼和上下界剪枝"；
   - 另写一个独立实现，在测试中交叉验证。

## 6. 不重复
- 每道题生成指纹：模式 + 区域布局 + 给定数 + 笼，用纯 JS 实现的哈希（如纯 JS 版 SHA-256）计算，不依赖 crypto.subtle。
- 经典、对角线、锯齿、武士：计算指纹前，先按数字首次出现的顺序重新编号，挡住"换个数字标签"的伪新题。
- 杀手：数值本身有意义，不重新编号。
- 已发放的指纹持久保存并包含在备份里；发题前检查，撞了就重新生成。

## 7. 游戏功能（全部为触控操作）
- 输入：
  - 点格再点数字键；可切换"数字锁定模式"（先选数，再连续点格）。
  - 笔记开关按钮；长按数字键 = 对所选格切换该数字的笔记，不改变当前模式。
  - 底部工具条：撤销、擦除、笔记、提示。
  - "更多"菜单：重做、重开本题、放弃本局、分享、导入、备份。
- 笔记：
  - 格内显示 3×3 小数字；
  - 填数后自动清除相关格的同数笔记（可关闭）；
  - "自动填候选"按钮，使用后计为用了辅助。
- 高亮：所选格所在行、列、宫，以及对角线、锯齿区域、所在笼；相同数字；含该数字的笔记。
- 杀手组合助手（可关闭，使用计入辅助）：选中格时显示所在笼的全部可能组合，并划掉已被排除的组合。
- 查错：
  - 三种模式：关闭 / 规则冲突提示（默认，不泄露答案）/ 对照答案即时判错（显示错误次数，可选"错 3 次即失败"）。
  - 冲突不能只靠颜色表示。
- 数字键盘显示每个数字的剩余个数，填满后变暗。
- 提示（三段式，提示次数计入成绩）：①标出可推进的区域 ②说出技巧名 ③完整讲解，可一键应用。
- 无限撤销/重做，包含笔记和提示操作。
- 计时与暂停：
  - 暂停时遮盖盘面；
  - 切到后台、锁屏、来电、分屏失焦时自动暂停。
- 残局永久保存：
  - 每一次操作后立即写入存档，包括盘面、笔记、完整撤销/重做历史、计时、提示与错误计数。
  - 杀进程、断电、系统回收内存后重新打开，都要原样继续，连撤销历史也在。
  - 写入要防半截损坏：采用事务写入 + 上一份有效存档兜底。
- 未完成列表：
  - 所有未完成的局都保留，每局显示模式、难度、进度百分比、已用时间、最后游玩时间；
  - 残局不自动覆盖、不过期，直到做完或我手动放弃（放弃需二次确认）；
  - 开新局不会顶掉旧残局；首页一键"继续上一局"。
- 历史记录：每局完成后记录日期、模式、难度、用时、提示数、错误数，可以按模式筛选查看。
- 完成：
  - 按全部规则校验；
  - 播放完成动画与音效；
  - 显示成绩卡：用时、提示数、错误数、难度分、是否新纪录。
- 统计：按"模式 × 难度"统计局数、胜率、最佳/平均用时、连胜。
- 分享/导入：
  - 分享码内含完整题面数据和格式版本号（不要只存种子）；
  - 用 navigator.share 发出，不支持时复制到剪贴板。
- 设置：
  - 主题：浅色 / 深色 / 跟随系统；
  - 音效开关与音量；
  - 各项高亮开关、查错模式、自动清笔记、显示计时器；
  - 震动：只在支持 navigator.vibrate 的设备上显示（Android）；iOS 隐藏此项。

## 8. 音效（Web Audio 实时合成，不用外部音频文件）
- 各操作的音色：
  - 填数：短促柔和的马林巴质感，数字 1–9 映射到五声音阶的不同音高；
  - 笔记：更轻、更高、更短；
  - 擦除：短促下滑音；
  - 撤销/重做：轻微回拨声；
  - 冲突/错误：低沉柔和的双音，不刺耳；
  - 完成一行/列/宫/笼：三音上行琶音；
  - 某数字全部填完：清脆铃声；
  - 提示：柔和钟声；
  - 通关：约 1.5 秒的小段胜利旋律。
- 技术要求：
  - 主音量节点加压缩器，防止爆音；限制同时发声数，快速连点不叠爆。
  - 首次触摸时创建或恢复 AudioContext；从后台切回时自动恢复。
  - 支持时设置 navigator.audioSession.type = "ambient"，不打断我正在听的音乐。
- 设置页注明：iPhone 静音模式下网页音效不会播放，这是系统行为；Android 上音效跟随媒体音量。

## 9. 视觉与布局
- 风格：
  - 安静、精致、有质感，不花哨也不简陋；
  - 浅色：暖白纸感背景 + 墨色数字 + 单一强调色；深色：深灰蓝背景；
  - 对比度达到 WCAG AA。
- 盘面：
  - 用 SVG 绘制，高分屏下锐利；
  - 细格线 1px，宫线 2–2.5px；
  - 给定数用墨色粗体，玩家数字用强调色，笔记用小号灰色；
  - 高亮层级：所选格 > 相同数字 > 相关单元；装饰与高亮色互不冲突。
- 装饰：
  - 杀手笼：虚线内缩约 4px；和数写在左上角并带底色遮挡，该格笔记避开这个角；选中时加深所在笼的轮廓。
  - 对角线：细线。
  - 锯齿区域：粗边框 + 可选淡彩底色。
  - 每个模式配图例。
- 布局：
  - 竖屏从上到下：顶栏（模式、难度、计时、暂停、设置）→ 盘面（占满宽度减边距）→ 工具条 → 数字键盘。所有操作键在屏幕下半部，单手拇指可达。
  - 横屏、折叠屏展开、分屏：盘面在左、键盘在右；任何宽高比都不能错乱或溢出。
- 武士数独：
  - 整盘显示时每格只有约 20px，无法准确点选。默认把单个子盘放大到满宽，填数只在放大视图进行。
  - 上方放 5 个子盘缩略图，点击切换，缩略图实时反映进度。
  - 共享宫加角标，注明它同时属于哪两个子盘。
  - 另设"总览"视图：可双指缩放、平移，只用于查看。
- 动效：
  - 时长 150–250ms：填数轻弹、单元完成波纹、通关整盘涟漪。
  - 按时间而不是帧数驱动，保证 60/90/120Hz 屏幕上速度一致。
  - 尊重 prefers-reduced-motion。
  - 不做常驻循环动画；页面隐藏时停止所有计时器和动画。

## 10. 双平台适配（逐条实现）
通用：
- 触摸输入：
  - 点按、长按、拖动、双指缩放统一用 Pointer Events 实现；
  - 长按用"计时器 + 移动阈值"判定，pointercancel 时取消。
- 触控目标 ≥48px，按下有即时视觉反馈。
- 防误触：
  - touch-action: manipulation；
  - -webkit-tap-highlight-color: transparent；
  - user-select: none 与 -webkit-touch-callout: none；
  - 在盘面和按键上拦截 contextmenu；
  - overscroll-behavior: none。
- 安全区：
  - viewport-fit=cover + env(safe-area-inset-*)，并提供回退边距；
  - 高度用 100dvh，回退 100vh；
  - 兼容灵动岛、刘海、挖孔屏、手势导航条和三键导航。
- 字体：
  - 数字用内嵌的开源字体子集（woff2，OFL 许可），保证两端外观一致；
  - 中文用系统字体栈：苹方、HarmonyOS Sans、MiSans、Noto Sans CJK。
- 字号缩放：
  - 设置 -webkit-text-size-adjust: 100%；
  - 系统或浏览器字体放大到 200% 时布局不崩；
  - 盘面数字大小只由格子尺寸决定。
- 深色：声明 <meta name="color-scheme" content="light dark">，并提供自己的深色主题，避免安卓"强制深色"把配色反转乱掉。

iOS 专项：在 Safari 下拦截 gesturestart，防止页面被双指缩放。

Android 专项：
- 返回键：
  - 打开弹窗、菜单、武士放大视图、说明页时，调用 history.pushState；
  - 按返回先关闭最上层界面；对局界面返回首页；只有在首页按返回才退出。
- 震动：用 navigator.vibrate 短震 10–20ms，可以关闭。
- 国产浏览器的"添加到桌面"表现不一，说明页推荐用 Chrome 安装。
- 用 4 倍 CPU 降速模拟中低端安卓，生成速度和动画流畅度都要达标。

## 11. 游玩说明（游戏内完整呈现）

## 12. 测试与验收（必须实际运行，PR 的 CI 全绿）
1. 批量生成并逐题验证。
   - 数量：
     - 经典、对角线、锯齿、杀手：1–3 档各 ≥200 道，4 档 ≥50 道，5 档 ≥20 道；
     - 武士：1–3 档各 ≥50 道，4 档 ≥20 道，5 档 ≥10 道。
   - 每道题都要检查：
     - 独立校验器确认答案满足全部约束；
     - 两个独立求解器都确认解数恰为 1；
     - 给定数与答案一致；
     - 技巧求解器不靠猜就能解完，且档位与标签一致；
     - 指纹不重复。
   - CI 上可用较小样本；完整样本至少在每个里程碑结束时跑一次，并记入 PROGRESS.md。
2. 结构检查：
   - 杀手：笼连通、笼内不重复、笼和等于答案之和、全部笼恰好覆盖 81 格。
   - 锯齿：9 个区域各 9 格且连通。
   - 武士：4 个共享宫在两个子盘中的数字一致。
3. 经典 9×9 唯一解题的给定数不可能少于 17 个，出现就说明有 bug。
4. 用已知难度的经典题检验评级器：
   - 纯靠单数就能解的题判 1 档；
   - 公认超难题判为"超出 5 档"并拒绝，且不能卡死。
5. 性能：记录每个模式每档生成耗时的中位数和最大值，正常 CPU 与 4 倍降速各一份。
6. 存档健壮性：
   - 连续快速操作后重开，数据完整；
   - 模拟写入过程中关闭页面，重开后能恢复到最后一份有效存档；
   - 多个残局并存互不干扰；
   - 旧版本数据结构能迁移到新版本（写迁移测试）；
   - 模拟 Service Worker 更新，存档不丢。
7. 端到端测试（Playwright，使用 iPhone 与 Pixel/Galaxy 设备配置，WebKit 与 Chromium 都跑）：
   - 功能：填数、长按记笔记、撤销/重做、三种查错模式、提示、暂停、残局列表与继续、放弃确认、通关、历史记录、分享码导入导出、备份导入导出、武士子盘切换与总览缩放。
   - 安卓返回：用浏览器后退模拟返回键。
   - 离线：首次加载后断网，冷启动、开新局、继续残局都正常。
   - 子路径：以 /<仓库名>/ 为 base 构建，在子路径下跑 E2E。
   - 字号：200% 字体放大下布局正常。
   - 截图：竖屏 320×658、360×800、393×852、412×915、440×956 各一张，横屏一张；浅色、深色两种主题各截一遍。
8. 最终输出：
   - 自检报告，写进 PROGRESS.md 并在对话中摘要：已实现功能、未实现项及原因、各项测试的真实数字、最低支持版本、已知限制。
   - 真机检查清单，我会在 iPhone 和安卓手机上各跑一遍：
     - 两端：安装到主屏幕、飞行模式下游玩、杀进程后恢复残局（含撤销历史）、多残局并存、更新后存档仍在、备份跨平台恢复、音效；
     - 仅 iPhone：静音键对音效的影响；
     - 仅安卓：返回键行为、震动、强制深色下的显示、系统字体放大。
